# 最短填写路径（fast-path）

> 现场填写会话的**固定执行序**。目标：精准且快——每一步都是"第一个完全可选项"，
> 每一次验证都对应一个**已发生的失败**，没有为安心而做的检查。
> 内容全部来自既有实测（`docs/bridge.md` / `docs/stations.md` §十六 / AGENTS §2.8 / §2.10），
> 本文零新代码、零新测试——本文自己就是 ponytail 那句"最好的代码是没写的代码"。
> 落地决策：用户 2026-10-29，吸收 stop-that-shit + ponytail 精髓进填写现场。

## 适用边界（先划清，别在 5 分钟里做工程化）

- **只适用于 adapters.js 已有注册项的站点**（inject 后 adapter ≠ generic）。
- 全新站点 → 走 `docs/stations.md` 的整理流程（§十四 / §十五），那是开发任务，不是填写任务。
- 现场发现的新问题**记入三清单带出，不当场修**（AGENTS："先填表后做工程化"）。

## 执行序

### 1 · 开场三步（一次，不重复）

1. `node scripts/status.mjs` —— **全程唯一一次**。中途报错才再查（那是诊断，不是预防）。
2. `navigate`（固定 session 名：`fp-<站点>-<日期>`，不复用旧名——同名会抢 tab 绑定，
   把数据写进别人的页面）。
3. inject → 确认回的 adapter 不是 `generic`（generic = 页面被切走 / 站点无注册项，先处理这个再谈填写）。

### 2 · 解析器优先（第一填充者）

站内有简历解析器就**先传简历**：上传 → 等稳定 → `scan()` → **只补增量**。
解析值沿用，不全量重填。省掉的是整个"文本字段批量写入"环节，这是最大的单项提速。

### 3 · 一次 scan 定全盘

`scan()` 的输出就是工作清单：`manual` / `emptyRequired` 直接进待办。
**不重复扫**——页面没有别人动的时候，第二次 scan 不会给出新信息
（"有没有别人动"由第 5 步提交前那一次兜底）。

### 4 · 通道决策表（一次选对，不试错）

| 字段形态 | 通道 | 依据 |
| --- | --- | --- |
| 文本 / 文本域 | `fillTexts` **一次打包全部**，不逐条发 | 引擎自带回读（ok/failed/retried） |
| 日期（可直接输入） | `fillDate`；只有年份的先填 `01` | R4 用户裁定 |
| Moka 单月（毕业时间） | `fillMonthRange('YYYY-MM')` 不传 to | §16.2 |
| Moka 普通下拉 | `pickOption` | §16.2 |
| Moka 级联（`sd-Dropdown`） | **手动**（两站形态不同，未自动化） | §16.4 |
| 北森下拉 / 单选 | `choose.mjs` / `setChoice` | §16.2 |
| 复合字段（手机号 addon 等） | **拒写 → 手动清单**（读得到 ≠ 写得对） | §16.1#3 |
| 免疫类型（manualTypes） | 跳过 → 手动清单 | 适配器 |
| 标签页在后台时的文本 | `filltext.mjs --set`（原生 fill，不吃节流） | bridge.md |

### 5 · 提交前一次 scan（全程第二次，也是最后一次）

寒武纪实证：同页可能有并发操作把字段清掉 / 改掉。这一扫是**唯一**保留的复扫。
同时做**解析器权威字段比对**：籍贯 / 城市 / 日期这类"看起来最权威"的逐项核
（兆易实证：解析器把籍贯填成了现居地；学校姓名对得上不代表籍贯对得上）。

### 6 · 三清单收尾（5 分钟到点强制）

已填 / 待手动 / 待确认。到点即收，不带"再试一次"。

## 不做清单（仪式性动作，砍掉的理由）

| 不做 | 为什么砍 |
| --- | --- |
| 预防性 status 重查 | 报错才查；没报错时查了也不改变动作 |
| rescan 循环 | 第 3 步已定全盘，第 5 步已兜并发 |
| 外层整页 evaluate 回读 | `fillTexts` 自带回读；只对 `failed` 字段手动核 |
| 手搓 evaluate 批量写 | 苏纳静默错写的源头；文本一律走 `filltext.mjs`（三条纪律已内建：清标记 / 一次性前缀 / 按 label 回读） |
| 常驻监督 agent | 已裁定闸门化（CVTE 实测：常驻 8 秒自杀，每步唤醒会吃光预算），红线 1/3/4 由执行者自带计数器守 |
| 同参数第三次重试 | §2.8 红线 3；换通道或转手动 |
| 现场修适配器 / 加防御 | 记入清单带出；工程化在填写会话之外做 |

## 不砍清单（每条挡一个已发生的失败，砍了会重蹈覆辙）

| 保留 | 挡的是什么（实证） |
| --- | --- |
| `composite-field` 拒写 | 北森手机号写错位置 |
| `tab-hidden` 入口守卫 | 后台标签页 30 秒不触发的无限等待 |
| 提交前 scan() | 寒武纪同页并发操作清字段 |
| 解析器权威字段比对 | 兆易籍贯填成现居地 |
| `filltext.mjs` 三条标记纪律 | 苏纳读写两边错到一起（报告 14/14，实际写错 3 个） |
| 读数铁律：拿不准一律报空 | 假"已填"会交出空必填表（§16.1） |
| 隐私三层闸门 | 真值进历史 = 删库重建 |

> 这两张表是同一个判据的两面（stop-that-shit §4）：**说得出挡哪个失败的留，说不出的砍。**
