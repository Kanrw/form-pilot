# 最短填写路径（fast-path）

> 现场填写会话的**固定执行序**。目标：精准且快——每一步都是"第一个完全可选项"，
> 每一次验证都对应一个**已发生的失败**，没有为安心而做的检查。
> 内容全部来自既有实测（`docs/bridge.md` / `docs/stations.md` §十六 / AGENTS §2.8 / §2.10），
> 本文零新代码、零新测试——本文自己就是 ponytail 那句"最好的代码是没写的代码"。
> 落地决策：用户 2026-10-29，吸收 stop-that-shit + ponytail 精髓进填写现场。

## 适用边界（先划清，别在 5 分钟里做工程化）

- **只适用于 adapters.js 已有注册项的站点**（inject 后 adapter ≠ generic）。
- 全新站点 → 走 `docs/stations.md` 的整理流程（§十四 / §十五），那是开发任务，不是填写任务。
- 现场发现的新问题**记入三清单带出，不当场修**（AGENTS："先填表后做工程化"）。

## 执行序

### 1 · 开场三步（一次，不重复）

1. `node scripts/status.mjs` —— **全程唯一一次**。中途报错才再查（那是诊断，不是预防）。
2. `navigate`（固定 session 名：`fp-<站点>-<日期>`，不复用旧名——同名会抢 tab 绑定，
   把数据写进别人的页面）。
3. inject → 确认回的 adapter 不是 `generic`（generic = 页面被切走 / 站点无注册项，先处理这个再谈填写）。
4. **`document.hidden === true` 时，先发 cdp `Page.bringToFront`，再谈填写。**
   它返回 `activation:"focus-emulation"`，不抢用户焦点，但页面变 `hidden:false` ——
   引擎全部异步方法（`fillTexts`/`pickOption`/`fillDate`/`addRow`）与 `choose.mjs` **当场恢复**。
   用完发 `Emulation.setFocusEmulationEnabled {enabled:false}`。
   **这是 2026-10-29 的教训**：明明这条早已实测在册，那一轮却因 `hidden:true` 直接切了下等通道
   （filltext 逐条），结果是 8 个下拉全灭、还被误当成"choose 判据失配"。**先 cdp，再考虑降级。**

### 2 · 上传简历（硬规则，不只是"有就传"）

**必须先找上传入口，找到了就传**，然后才谈手动填。2026-10-29 实证的差距：

| | 字段数 | 自动填入 |
| --- | --- | --- |
| 不传简历、手工填 4 分 44 秒 | 41 | 13（32%） |
| 传简历后 | **53**（解析器自己加了行） | **26（49%）** |

判据（**别再照抄上次那个错判据**）：全页找 `input[type=file]`，**不看它有没有 `.form-item` 里的
label**——piotech 的 file input 的 `accept` 为空、`label` 为空，但旁边就是整行的「上传简历」入口
（`DIV` 文本 "上传简历"，宽 800）。同时扫文本含「上传简历 / 重新上传 / 导入简历」的可点元素。

上传后 **必须 rescan**：解析器会覆盖已填值（实测清掉了通讯地址、英语等级成绩、技能三项），
所以顺序是 **上传 → 等稳定 → scan → 修补被清掉的 → 只补增量**。解析值沿用，不全量重填。

站内确实没有上传入口（全页零 file input）才跳过这一步，并在报告里写明判据。

**★ 顺序只能是"先传后填"，一旦手填过就别再碰上传入口。** 2026-10-29 实测（21:03 的一次重新解析）：
项目名称被截短（去掉冒号后的副标题）、职务被清空、描述被重写成「副标题 | …」的拼接、
教育 3 行被压成 2 行、日期全部取整到 `01` 月。**重新解析会覆盖所有已填内容**——包括你刚手工改对的。
所以中途若必须重新上传，**视为整表作废**：重新 scan → 全量核对（不是只补空白）→ 重填。

### 3 · 一次 scan 定全盘

`scan()` 的输出就是工作清单：`emptyRequired` 是要填的，**`manual` 原样交给使用者**
（那就是全部选择项，不要动手试）。

**不重复扫**——页面没有别人动的时候，第二次 scan 不会给出新信息
（"有没有别人动"由第 5 步提交前那一次兜底）。

### 4 · 通道决策表（一次选对，不试错）

| 字段形态 | 通道 | 依据 |
| --- | --- | --- |
| **文本 / 文本域（唯一由 agent 填的类）** | **`filltext.mjs`（桥 `click` 聚焦 + 桥 `fill`）**，`--json` 一次多字段、重名用 `index`。**React 受控站点上不要用引擎 `fillTexts`**——它是页内 JS 设 value + 合成事件，DOM 有值但**不进 React state**，任何重渲染都刷回旧值 | 2026-10-29 piotech 对照实验：同一批字段，`fillTexts` 写的 12 个**分钟级全丢**；`filltext` 写的 12 个经"点开下拉触发重渲染"后**长度全等**（20,21,189,27,51,200,18,38,103,15,39,175） |
| **所有选择项 —— 下拉 / 单选 / 复选 / 日期 / 级联** | **不填，留给使用者**（用户裁定 2026-10-29）。`scan()` 的 `manual` 清单直接原样交出去，**不要**再试 `choose.mjs` / `fillDate` / 日历面板 | 现场实测性价比：agent 侧每个都要 cdp + 面板 + 逐项点击，失败率高；使用者手动几秒完成 |
| 复合字段（手机号 addon 等） | 拒写 → 手动（读得到 ≠ 写得对） | §16.1#3 |
| 多行经历（教育/项目/实习…） | **先数默认行数，只补差额**点「添加X」 | 教育区默认 3 行、项目区默认 1 行；多点了还要倒着删 |
| 添加/删除行按钮 | 裸 DIV → 按「文本最短 + 无子元素」定位，**页内合成 `MouseEvent` 且与定位原子**（跨桥往返会被 React 换掉节点）。删行按 DOM 结构定位 + 非空护栏 | 2026-10-29 实测：合成点击有效（64→75） |
| 标签页在后台时的文本 | **先按第 1 步第 4 条 cdp 回前台**，再 click + fill | bridge.md + 2026-10-29 |

### 4b · 档案取值：时间是 `period`，不是 `from`/`to`

`education[]` / `projects[]` 的起止时间在 **`period`**（`YYYY-MM-DD -- YYYY-MM-DD` 或 `... -- 至今`），
`from` / `to` 是 `undefined`。取任何档案值前先 `Object.keys()` 看一眼，**别按语感猜键名**——
2026-10-29 用 `from`/`to` 取值，7 组教育/项目时间一个都没填上。

**解析器给的日期一律要核对**（第 5 步）：实测它把日期取整到 `01` 月、还会把下一段经历的时间
错位塞进上一行（本科的 2018/2022 被填进硕士行）。日期控件多为 `phoenix-select__input` + 月历面板，
`filltext` 与桥 `fill` 都只写入不落值（诚实失败）→ 只能真实点击面板，按消耗归手动。

### 5 · 提交前一次 scan（全程第二次，也是最后一次）

寒武纪实证：同页可能有并发操作把字段清掉 / 改掉。这一扫是**唯一**保留的复扫。
同时做**解析器权威字段比对**：籍贯 / 城市 / 日期这类"看起来最权威"的逐项核
（兆易实证：解析器把籍贯填成了现居地；学校姓名对得上不代表籍贯对得上）。

### 6 · 三清单收尾

**已填（文本/文本域 + 加行） / 待手动（全部选择项，原样列给使用者） / 待确认（解析器值可疑的）**。

分工（用户裁定 2026-10-29）：**agent 只负责文本框**，选择项使用者自己点。
所以收尾不做"这个下拉我再试一次"——直接列清单，交人。

## 不做清单（仪式性动作，砍掉的理由）

| 不做 | 为什么砍 |
| --- | --- |
| **不做任何选择项（下拉 / 单选 / 日期 / 级联）** | 用户裁定 2026-10-29：他手动几秒就完成；agent 侧要 cdp + 开面板 + 逐项点击，性价比为负 |
| **不用引擎 `fillTexts` 写文本** | 页内设 value 不进 React state，重渲染即丢（2026-10-29 对照实验） |
| **因 `hidden:true` 直接切降级通道** | 先发 cdp（1 发、不抢焦点、页面转可见），再 click + fill |
| **跳过上传简历直接手填** | 传一次抵 26 个字段，且解析器会自己加行（41→53） |
| **新加的行走 `fillTexts` 后不复验** | 受控组件可能在重渲染时冲掉刚写的值（报 ok 但终扫为空）→ 写完等 ~600ms 再 scan 一次，不粘就重写 |
| 预防性 status 重查 | 报错才查；没报错时查了也不改变动作 |
| rescan 循环 | 第 3 步已定全盘，第 5 步已兜并发 |
| 外层整页 evaluate 回读 | `filltext.mjs` 自带按 label 回读；只对 `failed` 字段手动核 |
| 手搓 evaluate 批量写 | 苏纳静默错写的源头；文本一律走 `filltext.mjs`（三条纪律已内建：清标记 / 一次性前缀 / 按 label 回读） |
| 常驻监督 agent | 已裁定闸门化（CVTE 实测：常驻 8 秒自杀，每步唤醒会吃光预算），红线 1/3/4 由执行者自带计数器守 |
| 同参数第三次重试 | §2.8 红线 3；换通道或转手动 |
| 现场修适配器 / 加防御 | 记入清单带出；工程化在填写会话之外做 |

## 不砍清单（每条挡一个已发生的失败，砍了会重蹈覆辙）
