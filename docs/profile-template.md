# 个人档案模板

> **这里只放字段清单，不要填真实信息。** 值写在 `private/profile.json`；`private/` 已在 `.gitignore`，内容永不入库。
> 字段定义与三类分类的**唯一来源**是 `tools/profile.schema.mjs`；本文是它的人读镜像，也是 `--import` 的输入格式。

## 为什么放在仓库里

form-pilot 的目标是公开可用的引擎 + 适配器；个人信息是**每个使用者自己的输入**，不是项目资产。
两者物理隔离：`engine/`、`scripts/`、`tools/`、`skill/` 是共享的，`private/` 是你自己的。

引擎**只**通过 `fillTexts(map)` 收到"某个字段填某个值"。它不读 `private/`，
也不知道数据从哪来。`字段 → 值` 这一步由你在对话里确认，是三道闸门的第一道。

## 用法

```bash
# 从零开始
node scripts/profile.mjs --init      # 按 schema 建出空的 private/profile.json
node scripts/profile.mjs --ui        # 打开界面 http://127.0.0.1:8787

# 已经有一份手写的 private/profile.md
node scripts/profile.mjs --import    # 迁移成 profile.json，写入前自动备份成 profile.json.bak
```

界面里改完点保存即写回 `private/profile.json`；保存时格式不合法的字段会被拦下来，
不会让错值进档案。不想用界面也行：下面这份清单就是 schema 的镜像，
用编辑器直接改 json 一样可以，改完跑 `--check` 校验。

## 隐私检查（推送前必须跑）

```bash
git ls-files | grep -E '^private/' && echo "泄露！" || echo "OK"
git status --short --ignored | grep private     # 应显示 !! private/
```

两个命令任一异常，都说明 `.gitignore` 被改坏了，**不要推送**。

## 三类字段的处理约定

分类不写在数据里，写在 `tools/profile.schema.mjs` 的 `autofill` 上；界面、校验、映射表都按它走。
映射表（`--render`）只含 `auto` 与 `confirm`，`never` 一项都不出现 —— 这条由代码保证，不靠人记得住。

| 类别 | autofill | 例子 | 处理 |
| --- | --- | --- | --- |
| 可自动填 | `auto` | 姓名、学校、专业、GPA、项目描述 | 你确认映射后由引擎批量填 |
| 需逐项确认 | `confirm` | 求职意向、期望薪资、到岗时间 | 每项单独确认，不套模板 |
| **永不自动填** | `never` | 身份证号、银行卡号、密码、验证码 | 界面里关进朱砂虚线围栏、标"待你手动"；引擎不提供也不接受这类值 |
| 路径 | `path` | 简历、成绩单、证件照的本地路径 | 只做存在性校验；上传走桥，不经引擎 |
| 记录 | `note` | 科研来源、题目、每段结构 | 给人看的说明，不进映射 |

第三类是硬边界，不因"你已经在档案里写了"而放宽。档案里可以不写这些字段。
