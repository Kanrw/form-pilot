# 个人档案模板

> **这是模板，不要在这里填真实信息。** 复制到 `private/profile.md` 再填。
> `private/` 已在 `.gitignore`，内容永不入库。

## 为什么放在仓库里

form-pilot 的目标是公开可用的引擎 + 适配器；个人信息是**每个使用者自己的输入**，不是项目资产。
两者物理隔离：`engine/`、`scripts/`、`skill/` 是共享的，`private/` 是你自己的。

引擎**只**通过 `fillTexts(map)` 收到"某个字段填某个值"。它不读 `private/`，
也不知道数据从哪来。`字段 → 值` 这一步由你在对话里确认，是三道闸门的第一道。

## 用法

```bash
cp docs/profile-template.md private/profile.md
# 填完 private/profile.md，然后在对话里指定它：
#   "用 private/profile.md 里的资料填这个页面"
```

## 隐私检查（推送前必须跑）

```bash
git ls-files | grep -E '^private/' && echo "泄露！" || echo "OK"
git status --short --ignored | grep private     # 应显示 !! private/
```

两个命令任一异常，都说明 `.gitignore` 被改坏了，**不要推送**。

## 三类字段的处理约定

| 类别 | 例子 | 处理 |
| --- | --- | --- |
| 可自动填 | 姓名、学校、专业、GPA、项目描述 | 你确认映射后由引擎批量填 |
| 需逐项确认 | 求职意向、期望薪资、到岗时间 | 每项单独确认，不套模板 |
| **永不自动填** | 身份证号、银行卡号、密码、验证码 | 留空，标"待你手动"；引擎不提供也不接受这类值 |

第三类是硬边界，不因"你已经在档案里写了"而放宽。档案里可以不写这些字段。
