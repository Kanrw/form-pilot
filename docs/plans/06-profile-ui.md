# 06 · 个人档案界面：技术路线与设计

> 依据：`AGENTS.md §一`（隐私硬边界）、`§二`（工作纪律）、`03 §3/§4/§5`（零构建、jsdom、scripts 约定）、
> `05 §三`（三层架构与接口契约）。
> 用户决策（2026-09-22）：**技术路线 B**（本地 Node 单文件服务）；**视觉方向 A（登记表）**。
> C（源码 + 预览分栏）不做；B（问答向导）实现后由使用者判定"太累赘、没有用"，已整块撤掉（见 §六）。
> 数据模型采用 `private/profile.json` 唯一事实源（推荐项，用户未提异议）。
> **实施状态（2026-09-22）：Phase 1 与 Phase 2 均已落地**，`npm test` 35 例全绿。
> 实现与本规划的偏差集中在 §十三。

## 一、要解决的问题

现状：`private/profile.md` 由人手写，约 6KB、36 个固定字段位 + 3 类可重复区块。

**命名失败**（§2.3：每条防御对应一个已命名的失败）：

| # | 失败 | 后果 |
| --- | --- | --- |
| F1 | 字段漏填或格式写错（手机号少一位、时间写成 `2026-9`） | 错值跟着表单一起提交给第三方，当场看不出来 |
| F2 | 三分类（可自动填 / 需逐项确认 / 永不自动填）只活在提示词的散文里 | 某轮对话忘了"证件号码永不自动填"，安全性取决于模型的记性 |
| F3 | 附件路径写错 | 到填表当天才发现，且当天未必文件和网络都在手边 |
| F4 | 重复区块的段序号错位（教育 2 段写成 3 段、顺序反了） | 提交的经历与事实不符，且极难自查 |
| F5 | 档案在多个 checkout / 副本间漂移 | 不知道哪份是当前事实。**本工作区当前就没有 `private/`**（gitignored，每个 checkout 各一份） |

**目标**：把 F1–F5 变成代码能断言的事，而不是靠人记得住。

## 二、非范围

| 不做 | 原因 |
| --- | --- |
| 在目标页面注入侧栏/浮层表单 | 个人信息进入第三方 DOM，等于把档案交给站点 |
| 浏览器持久化（localStorage / IndexedDB / sessionStorage） | 会在 `private/` 之外留下第二份个人数据副本，且与文件漂移（F5 的变体） |
| 改 `engine/` 或新增 `__ja.*` 接口 | 引擎与档案之间的契约不变，仍是对话确认后的 `fillTexts(map)` |
| md ↔ 结构的双向解析 | `03 §2.4` 已否掉同类的"md↔js 脆弱抽取"，理由相同 |
| 富文本编辑器、模板/变量、自动生成文书 | 无命名失败。长文本逐题手写（`docs/profile-template.md §7`） |
| 打包器 / TypeScript / 框架 / 表单库 | `03 §3` 零构建；`+0` 三方依赖 |
| 多用户、登录、云同步、手机端 | 单机单人本地工具；多端会把数据推出 `private/` |
| 云文档/表格托管（腾讯文档、Excel） | 个人数据离开本机进第三方，与隐私立场相反 |

## 三、技术路线

| 路线 | 形态 | 否决/采用理由 |
| --- | --- | --- |
| **B · 本地 Node 服务** | `node scripts/profile.mjs --ui` → `127.0.0.1:8787`，`node:http` + `node:fs` 手写 | **采用**。唯一能在代码层强制"只写 `private/`"；`stat` 附件路径；复用项目唯一的测试设施（`node:test` + jsdom）；与 `03 §5` 的"零三方依赖 `.mjs`"约定一致 |
| A · 单文件 HTML | 双击即开，File System Access API 原地保存 | 补选。零进程，但仅 Chromium 能原地保存；用户可用目录选择器指向任意路径，**无法在代码层守卫写入边界**；逻辑难进 `node:test` |
| C · Vite + React + 表单库 | 构建型 SPA | 否决。**直接违反 `03 §3` 的零构建决定**，且给一个处理证件号的项目加上供应链面 |
| D · 只加 CLI | 不做界面，`--check` / `--import` / `--render` | 保留为 Phase 1 与永久回退路径，单独作为最终形态不够（不解决 F1） |
| E · 云文档/表格 | 托管方案 | 否决。数据离开本机 |

### 服务端三条硬细节

1. `server.listen(port, '127.0.0.1')` —— 不监听 `0.0.0.0`。
2. 校验 `Host` 头必须是 `127.0.0.1:<port>` 或 `localhost:<port>`，否则 403。
   命名失败：DNS rebinding —— 本机浏览器里的任意网页把域名解析到 127.0.0.1 后读写档案。
3. 不发任何 CORS 头。命名失败：跨源网页用 `fetch` 打本机端口。
   无 CORS 头时，`PUT` + `Content-Type: application/json` 会卡在 preflight，`GET` 的响应读不到。

启动时把**实际使用的绝对路径**打在页面上。命名失败：F5 —— 在 git worktree 里跑而 `private/` 属于主检出，
容易以为数据丢了或在第二个 checkout 里写出第二份。

## 四、数据模型

**两个文件，职责分离，互不复制。**

| 文件 | 角色 | 入库 |
| --- | --- | --- |
| `tools/profile.schema.mjs` | 字段定义：标签、类型、分类、校验规则、区段顺序 | 是（共享资产） |
| `private/profile.json` | **只有值**。不含 label/type/autofill | 否（gitignored） |

分类只写在 schema 里，**不写进数据文件** —— 否则同一个事实存两处，就是 F2 换了个位置。

```jsonc
{
  "version": 1,
  "updatedAt": "2026-09-22T12:40:00+08:00",
  "values": {
    "basic.name": "",
    "basic.phone": "",
    "basic.idNumber": "",
    "education": [
      { "school": "", "period": "", "degree": "" }
    ],
    "experience": [],
    "answers": [
      { "scope": "", "question": "自我介绍（300 字内）", "answer": "" }
    ],
    "attachments.resumeCn": ""
  }
}
```

**格式规则（为可读性，不是为 git）**：

- 2 空格缩进，**每个字段一行**，键序固定为 schema 顺序。
  命名失败：整片重排的 diff 让人无法肉眼核对"这次到底改了什么"（验收标准依赖这条）。
- 重复区块存为数组，段序 = 事实顺序（时间倒序由 UI 的"添加一段"位置决定）。
- 文件不含注释、不含 label。

**为什么不做 md 双向解析**：`private/profile.md` 里有注释、来源指针、逐题长文本三类非表格内容，
回写必然丢东西。改为单向 `--import` 一次性迁移，迁移后 md 停用、不并行维护（消除两处事实源）。

## 五、字段与分类（唯一来源：`tools/profile.schema.mjs`）

**分类枚举**（键为 `autofill`，单值）：

| 值 | 含义 | 进映射 | 计入完整度 | 界面 |
| --- | --- | --- | --- | --- |
| `auto` | 客观事实、跨表单口径一致 | 是 | 是 | 墨蓝方点 ·「可自动填」 |
| `confirm` | 口径随公司/岗位而变，需判断 | 是，逐项确认 | 是 | 赭石方点 ·「需确认」 |
| `never` | 引擎不提供也不接受 | **否** | 否 | 朱砂虚线围栏 |
| `path` | 值是一个本地路径，上传走桥的 `upload` | 否 | 是 | 路径输入 + 存在性徽标 |
| `note` | 纯记录，不给引擎 | 否 | 否 | 普通输入框，无标记 |

「计入完整度」= `SCORED`（`tools/profile.schema.mjs`）。`never` 不计：留空才是它的正确状态，
算进分母等于永远扣分。`note` 不计：那是给人看的说明，而且 `answers` 预置的三个题目
会让完整度一开始就不是 0，用户第一眼就失去判断。

**字段清单不在这里复制。** 唯一来源是 `tools/profile.schema.mjs`（当前 14 个区段、84 个字段位）。
本文转述一份的结果只会是两处事实源、两处漂移 —— 要字段表就跑：

```bash
node --input-type=module -e "import('./tools/profile.schema.mjs').then(m=>console.log(m.SECTIONS.map(s=>s.short).join(' / ')))"
```

区段划分（按使用者真实维护的《个人资料卡》对齐，不是照模板猜的）：
基本信息 / 教育经历 / 在校职务 / 社团与组织活动 / 实习与工作经历 / 科研与项目经历 /
论文与成果 / 获奖 / 技术能力 / 证书与语言 / 求职意向 / 自我评价 / 常见长文本答案 / 附件清单。
其中**可重复**的有 9 个（教育、在校职务、社团、实习、项目、论文、获奖、技术能力、长文本、附件）。

**预置**：`answers` 预置 3 条空条目（自我介绍 300 字内 / 为什么选择这家公司 / 职业规划），
`education`、`experience` 初始为空数组。
**计数**（页面上的「完整度 39 / 43」这类数字）**由 schema 现算**，不写死在代码或文档里。

## 六、界面设计

### 视觉方向（方向 A：登记表）

- **视觉主题**：档案册 / 登记表 —— 冷白纸面、1px 墨灰细线分栏、等宽小字字段名、无卡片无阴影；
  全页唯一的重色是分类标记（墨蓝 = 可自动填、赭石 = 需确认、朱砂 = 永不自动填）。
- **内容计划**（工具型，无 hero）：顶栏（文件路径 · 完整度 · 保存态 · 本地徽章）→
  左轨（9 项区段 + 完成度）→ 主区（当前区段字段登记表；重复区块在段内做子表）→
  右栏（分类统计 · 待你手动清单 · 导出）。
- **交互主题**：只有保存驱动动效 —— 保存时该行基线一条 1px 墨线扫过（140ms，仅 `transform`/`opacity`），
  顶栏时间戳更新。键盘触发的区段跳转不动画。

### 方向 B：问答向导 —— 已撤掉（2026-09-22）

第一版实现过完整的一屏一问向导（步骤列表一次冻结、跳项、空区段先问"要不要加一段"），
使用者看过之后判定**"写得太累赘、没有用"**，因此整块删除：顶栏视图切换、
`buildWizardSteps` / `expandGate` / `renderWizard`、向导样式、两例向导用例、人工清单里三行，一处不留。

**为什么它没用**（记下来，免得以后又加回来）：

- 登记表的密度够高（一屏 12+ 字段）。84 个字段位逐条问要问上百屏，比一次看完一栏慢得多。
  向导适合"从零填一份新表单"，不适合"维护自己的档案"。
- 档案维护的真实动作是**回来改几格**，不是"从头走一遍"；向导每次都要重新生成步骤列表，
  而它那个列表还得冻结住才不会被自己的编辑打乱。
- 它引入的状态（冻结的步骤数组、跳过集合、闸门展开）比登记表主体还多，
  而这些状态只服务于"走一遍"这一个动作 —— 正是本项目 §2.3 说的"说不清挡住哪个失败的层"。

### 三分类的渲染规则

- 标记 = 6px 方点 + 11px 文案，放在字段行最右列；颜色只由 `autofill` 决定。
- **围栏不是区段，是渲染规则**：任何 `autofill === 'never'` 的字段，无论属于哪个区段，
  都渲染进朱砂虚线围栏并附一句"这里的值不进任何映射，也不会随表单提交"。
  当前只有 `basic.idNumber` 一个字段落在围栏内；以后要加，只需在 schema 加一行，界面自动跟上。
- `path` 字段右侧给存在性徽标（存在 = 墨灰勾形文字「已找到」，不存在 = 朱砂「未找到」），
  由 `GET /api/profile` 顺带返回的 `stat` 结果驱动。

### Token（先定死，再写第一行 CSS）

| 角色 | 值 | 用途 |
| --- | --- | --- |
| `--paper` | `oklch(0.978 0.003 92)` | 页面底色 |
| `--ink-1` | `oklch(0.22 0.008 80)` | 主文字、字段值 |
| `--ink-2` | `oklch(0.46 0.008 80)` | 字段名、次要文字 |
| `--ink-3` | `oklch(0.56 0.006 80)` | 提示、计数 |
| `--rule` | `oklch(0.905 0.004 85)` | 1px 分隔线 |
| `--rule-2` | `oklch(0.82 0.005 85)` | 强调分隔线、输入框边 |
| `--auto` | `oklch(0.46 0.075 245)` | 墨蓝 · 可自动填 |
| `--confirm` | `oklch(0.58 0.10 72)` | 赭石 · 需确认 |
| `--never` | `oklch(0.52 0.15 28)` | 朱砂 · 永不自动填 |
| `--never-bg` | `oklch(0.96 0.02 28)` | 围栏底 / 徽章底 |
| `--focus` | `oklch(0.55 0.10 245)` | 焦点环 |

- **单层表面 + 细线分层**：不使用嵌套 surface，因此不涉及"邻近表面至少 4% 明度差"的问题，也避免不可见卡片。
- 圆角阶梯：`3px`（徽章/方点）· `6px`（输入框/围栏）· `10px`（面板）· `pill`（状态徽章）。
- 间距阶梯：`4 / 8 / 12 / 16 / 24 / 32`。
- 字体：系统栈 `-apple-system, "SF Pro Text", "PingFang SC", "Noto Sans SC", sans-serif`；
  字段名与计数用 `ui-monospace, "SF Mono", Menlo, monospace`。**不引网络字体** —— 本地工具必须离线可用，
  个性来自版式与细线，不来自字体。
- 字号 11–15px，字重只用 400 / 500；计数与数字列 `font-variant-numeric: tabular-nums`；
  CJK 正文行高 1.7。
- 断点：1280 三栏 → 1024 右栏折到顶栏 → 768 左轨变横向区段条。

### 动效与可达性

- 动效：保存时该行下沿 1px 墨线 `scaleX` 扫过 + 顶栏时间戳更新（140ms `ease-out`，仅 `transform`/`opacity`）；
  按钮按下 `scale(0.96)`；**区段跳转、Tab 移动、字段切换一律不动画**（高频动作）。遵循 `prefers-reduced-motion`。
- 每个输入框有配对的 `<label for>`；焦点态 `focus-visible` 2px `--focus` 环 + 1px 偏移，不写 `outline: none`。
- 首个可聚焦元素是"跳到字段区"的跳转链接。
- 对比度：`--ink-2` / `--ink-3` 在 `--paper` 上均 ≥ 4.5:1；三色标记只用于文字与方点，不用于正文色。

## 七、接口契约

### schema 导出 shape

```js
{
  sections: [
    { key: 'basic', label: '基本信息', repeatable: false,
      fields: [{ key: 'name', label: '姓名', type: 'text', autofill: 'auto',
                 options: null, pattern: null, hint: '' }] },
    { key: 'education', label: '教育经历', repeatable: true, fields: [ /* … */ ] }
  ]
}
```

### 数据 shape

见 §四。键序 = schema 顺序；`PUT` 全量写回（不做增量补丁，少一层状态）。

### CLI（`scripts/profile.mjs`）

| 参数 | 作用 | 退出码 |
| --- | --- | --- |
| `--init` | 用 schema 生成空的 `private/profile.json`（已存在则拒绝，除非 `--force`） | 0 / 1 |
| `--import <md>` | 把 `private/profile.md` 解析进 json；写入前备份为 `private/profile.json.bak` | 0 / 1 |
| `--check` | 校验格式与非空；stdout 输出 `{ok, errors[], warnings[]}` | 有 error → 1 |
| `--render [--out <md>]` | 渲染"字段 → 值"映射表（markdown），`never` 字段不出现 | 0 / 1 |
| `--ui [--port 8787]` | 起本地服务 | 0 / 1 |
| `--root <dir>` | 指定仓库根（默认取当前工作目录），用于多 checkout 场景 | —— |

所有路径解析后必须落在 `<root>/private/` 内，否则拒绝并退出 1（代码层兑现隐私硬边界）。

**stdout 不回显任何字段值**，只回标签与计数。命名失败：值一旦进了终端回滚缓冲、日志、
或贴进对话的那一刻，档案就出了 `private/`。`--render` 是唯一例外 —— 它的用途就是给出映射表，
所以它没有 `--out` 时打到 stdout、有 `--out` 时只回文件路径不打印内容。

### HTTP（仅回环）

| 方法 | 路径 | 返回 |
| --- | --- | --- |
| `GET` | `/` | `tools/profile-editor.html` |
| `GET` | `/tools/*` | 白名单只放 `profile-editor.{html,css,js}`，其余一律 404（不做目录遍历） |
| `GET` | `/api/profile` | `{ schema, values, unknownKeys, filePath, legacyMd, legacyMdExists, stats, errors, warnings, pathChecks }` |
| `PUT` | `/api/profile` | body = `{ values, unknownKeys }`；有 error 时 400 **且不落盘**；成功则备份 + 写入，返回 `{ ok, savedAt, stats, errors, warnings, pathChecks }` |
| `GET` | `/api/mapping` | `text/markdown`，与 `--render` 同一份（`never` 一项都不出现） |
| `GET` | `/api/versions` | 版本列表（名字 + 覆盖项数）、版本目录、基准文件路径 |
| `POST` | `/api/versions` | body = `{ name, from? }`；从基准新建 = 空覆盖集，「复制当前版本」= 逐字带走覆盖集；重名 409 |
| `GET` | `/api/profile?version=<名>` | 基准 ⊕ 覆盖后的视图，附 `version` / `overrides` / `versions` |
| `PUT` | `/api/profile?version=<名>` | body = `{ overrides }`；**通用事实根本不在这个请求里**，改不动；白名单外的键 → 400 |
| `POST` | `/api/import` | 跑一次 md → json 迁移，只回计数不回值；已有内容且未带 `force` 时回 409 |

**所有统计与校验一律由服务端算，界面只渲染。** 两侧各算一遍就会有两个数字，
用户会先不信界面、再不信工具；`never` 是否泄漏也只在一个地方需要盯。

### 校验严重级

| 级 | 触发 | 行为 |
| --- | --- | --- |
| error | 格式不合法（手机号、邮箱、日期、时间区间） | `--check` 退出 1；界面行内红字，保存被拒 |
| warn | 建议字段为空 | 只提示。**留空比猜值安全**，不阻断 |
| warn | `never` 字段非空 | 提示"引擎不会使用此值"；不阻断，也不导出 |
| warn | `path` 字段指向的文件不存在 | 行内「未找到」徽标 |

### 实施中发现并修掉的问题（每条都有用例）

| # | 问题（命名失败） | 修法 |
| --- | --- | --- |
| 1 | 用户那份档案的字段写法与 schema 不同名（`微信号` / `GPA / 排名`），导入报 `ok` 却静默丢字段 | 字段加 `aliases`，比对时走别名 |
| 2 | 用户用 markdown 加粗当字段名（`**来源**：`，没有短横线），整行认不出来 | 标签去格式 + 允许无短横线；标签长度上限 24 字符，避免把正文句子当字段 |
| 3 | 未识别区段整段被丢，日志只说"已忽略"，不知道丢了什么 | 记下该区段内的字段名并回显（这次就靠它发现 §9 是说明文字而非字段） |
| 4 | `2000.02` / `2000 年 2 月` / `2019.09 - 2023.06` 被当成格式错 | 导入时归一化（点、斜杠、`年/月` → 短横线；区间统一成 `--`）。导入宽容、手输规范 |
| 5 | **档案比引擎还严**：schema 要求 `YYYY-MM-DD`，而 `fillDate` 本来就接受 `YYYY` / `YYYY-MM` 并把补的部分报在 `assumed` 里 | 日期与区间都放宽到"引擎能接受的最粗精度"。逼用户编一个日子，与"不猜值"的口径冲突 |
| 6 | 区间归一的左半边用允许尾随分隔符的贪婪写法，`2021 -- 2025` 被切成 `2021 -` + `-` + `2025`，凭空多一个短横线 | 每个分段都要求分隔符后必须跟数字。这是解析器 bug，不是数据写法问题 |
| 7 | 值里混着作者自己的批注（`（…推断，**待你确认**）`），会跟着表单提交出去 | 检测 `**` 与「待…确认」→ warn（不阻断：拦住只会让人没法保存，但必须说出来） |
| 8 | 改完 schema 不重启 `--ui`，界面继续用旧规则校验，报的错对不上文件内容 —— 看起来像代码 bug | 服务端按 schema 文件 mtime 判 `schemaStale`，界面顶部提示"重启一次 --ui 才生效" |

第 4/5/6 条合起来的效果：`--check` 在你那份真实档案上的 error 从 2 条降到 0 条。

### 第二轮：字段模型按使用者真实资料卡重建

第一版 schema 只有 8 个区段、46 个字段位，是照着 `docs/profile-template.md` 的模板抄的。
把它用到一份真实维护的《个人资料卡》上才发现：**模板只覆盖真实需求的一小半** ——
身高体重、婚姻状况、生源地、户口所在地、在校职务、社团经历、论文列表、获奖、自我评价、
附件清单在模板里都没有位置。使用者的原话是"根本就没有很好的将所需要的信息统计起来"。

改法（14 个区段 / 84 个字段位）：

| 变化 | 命名失败 |
| --- | --- |
| `research`（职责是"指个来源路径"）→ `projects` 可重复 6 字段 | 项目只在来源路径里，填表时拿不到内容，用户只能手工再写一遍 |
| `attachments` → 可重复 {用途, 路径} | 固定 5 个槽位装不下真实材料清单（实际 19 份） |
| 新增 在校职务 / 社团活动 / 论文与成果 / 获奖 / 技术能力 / 自我评价 | 这些是校园招聘表单的常规项，没有位置就只能散在别处 |
| `basic` 补 英文名 / 身高 / 体重 / 婚姻状况 / 生源地 / 户口所在地 / 海外居留权 / GitHub / ORCID / 挂科门数 | 表单逐个要，缺一个就得临时翻材料 |
| `education` 补 已获学位 / 培养类型 / 导师 / 学号 / 是否海外留学经历 | 在读博士的"学位"要如实填"无"，没有这一格就会填错 |

配套的三个 I/O 能力（都有用例）：

| 能力 | 命名失败 |
| --- | --- |
| 缩进续行并入上一个字段 | 项目描述、自我评价天然是多行；只取第一行等于悄悄截断 |
| `path` 字段的校验覆盖可重复区段 | 附件清单全在段里，只扫固定区段 → 19 份材料全部失去存在性校验 |
| 占位判定改成"拆开后每项都是选项词" | 和 `options.join` 逐字比：给 select 加第三个选项，老模板那行就被当成真值导进来 |
| 日期字段回显 ISO 值 | 原生日期控件按浏览器区域显示，en-US 下 `2001-01-01` 显示成 `10/02/2000`，会被读成 10 月 2 日 |

真实档案上的结果：`matchedFields 78`、`notes []`（没有一个标签对不上）、
`completeness 172/182`、`errors 0`、`warnings 0`；段数
教育 3 / 在校职务 1 / 社团 2 / 项目 4 / 论文 7 / 获奖 2 / 技术能力 4 / 附件 19。
界面上「待你手动」只剩 1 条：证件号码。

**证件号码刻意没有被写进文件**：它属 `never`，AI 不代填 —— 即使材料里就有。
这是那条硬边界第一次被真实材料检验，结果是守住了。

### 第三轮：日期默认到日

使用者原话："很多涉及到日期选择的部分，都需要精确到日，所以这个表单里面也应该默认先填写一个具体日期。"

两处改动：

1. **导入时把区间补到日**（`expandRangeToDay`）。约定：开始 = 该期间第一天，结束 = 该期间最后一天
   （`YYYY` → 年初/年末，`YYYY-MM` → 月初/月末，闰月按 `new Date(y, m, 0)` 取）。
   命名失败：表单的日期是"年 → 月 → 日"三级选择，档案里只存到月，填表时每一处都要现场补一个日子。
   **补了哪几处会在 `--import` 的输出里逐条报出来**（`assumedDates`）—— 补的值不能冒充事实。
   已经到日的值一律不动。
2. **界面里 `daterange` 改成两个原生日期控件**（原来是一行自由文本），结束留空＝至今。
   命名失败：日期这件事在档案里是手打、在表单里是选，两边不一致，而且手打的值不保证能过校验。
   只到月/年的旧值**不交给日期控件**（控件会把不合规的值显示成空，一保存就静默清掉），退化成文本框。

顺带纠正一个我自己的判断错误：日期控件按浏览器区域显示，这台机器上是 **DD/MM/YYYY**
（`2001-01-01` 显示成 `10/02/2000`），我上一轮说"会被读成 10 月 2 日"说反了。
ISO 回显仍然保留 —— 显示格式与存储格式不一致这件事本身会造成误读。

### 第四轮：分类的语义 + 界面上把分类讲清楚

使用者问："这些需确认的项，是什么意思？最后要如何确认？" —— **要问，就说明界面没写清楚**，
同时暴露一个分类错误：

| 问题 | 修法 |
| --- | --- |
| 4 个日期区间被标成 `confirm`，理由是"表单的日期三级选择难自动化" | 改成 `auto`。分类要回答的是"**值**需不需要人判断"，不是"**控件**难不难填"；日期精确到日之后值唯一，标错会让人以为每处日期都要再确认一遍 |
| 界面上只有分类名与计数，没有含义，也没说最后在哪一步确认 | 右栏加四行说明：三个分类各一句 + "怎么确认：点「映射表」复制给助手，它会按目标表单逐项列出核对"；分类行加 `title` 悬浮解释 |
| 文本框的 hint 当了占位符，又在下面重复显示一遍 | 有占位符的控件不再重复输出 hint（下拉与日期控件没有占位符，仍显示） |

**「需确认」的语义定下来**：值随公司/岗位的口径变（用词、选项集、薪资口径），
所以不套模板、每项单独过。当前 23 项：政治面貌 / 籍贯写法 / 紧急联系人（含第三方信息）/
已获学位（在读与转博的填法）/ 论文状态（审稿中要不要写）/ 求职意向 8 项 /
自我评价（按字数裁剪）/ 长文本答案（逐题写）。

**确认动作发生在对话里，不在界面上** —— 那是"填某一份具体表单"时的动作，不是维护档案时的动作。
刻意**不做**界面上的"已确认"勾选：口径随公司变，一次性勾选会过期，反而给人已经确认过的错觉。

### 第五轮：撤掉问答向导

使用者看完实现后判定向导"太累赘、没有用"，整块删除。删除范围与理由记在 §六「方向 B」。
这是本项目纪律 §2.3 的一个正例：那一层的状态（冻结步骤、跳过集合、闸门展开）
说不出挡住哪个具体失败；删掉之后登记表一行没动就完成了同样的工作。

认可这个流；两处收窄（都是为了让"乱"没有机会发生）：

| 收窄 | 命名失败 |
| --- | --- |
| 白名单只放 **9 个固定字段**（求职意向 8 项 + 自我评价），**长文本答案不进白名单** | 它自带 `scope`，本就能表达"按岗位换说法"；整段放进版本会出现"基准里新加的通用答案某些版本看不到"这种静默的漏 |
| 版本视图里**非白名单字段只读**（`readOnly` / `disabled` + 灰底） | 否则"我改了手机号"其实只改了某个版本，下次投别的岗位才发现 —— 这种错是静默的 |

**白名单是代码强制的，三处一起挡**：`validateOverrides()` 报错、`writeVersion()` 直接抛错（不许静默丢弃）、
界面把控件锁住。手改 json 也拦得住。

**文件与命令**

```
private/profile.json              基准档案（唯一事实源，84 个字段位）
private/profiles/<版本名>.json     只存差异：{ version, name, note, overrides: { 键: 值 } }
```

`--versions` 列出；`--new-version <名> [--from <版本>]` 新建；`--check / --render / --ui` 都可加
`--version <名>`，映射表表头会写明「口径版本：X（覆盖 N 项，其余来自基准档案）」。

**界面**：左上角下拉（基准档案 / 各版本·覆盖 N 项 / ＋新建版本 / 复制当前版本）；
版本视图顶部一条提示"只有口径字段能改"；被覆盖的行标琥珀色「本版本已改」并给「还原为基准」；
右栏多一块「本版本覆盖 N 项」列出是哪些。还原时用**服务端给的基准值**回填，
不在前端重新实现一遍"基准 ⊕ 覆盖"的合并（避免两侧各算一遍）。

**真实浏览器核对**（3 个临时版本，核对完已删）：切换后 `basic` 的 26 行全部只读、
