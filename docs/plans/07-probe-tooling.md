# 07 · 探针工具化：三方对抗记录与裁定

> 起因（用户 2026-09-22）：「我就是想要通过一些具体的工具包，来快速完成这个过程」。
> 同时用户否决了上一轮提出的"上传简历＝省活的杠杆"论点，理由：解析器会填错，最终仍要全量人工核对，
> 核验成本没下降。**该论据已作废，不得再作为项目价值主张引用。**
> 结果：`scripts/probe.mjs` 已落地，`npm test` 61 全绿。

## 一、三方主张

| 立场 | 核心主张 | 最强的一条 |
| --- | --- | --- |
| 实现派 | 做 `scripts/probe.mjs`，一次 evaluate 产出候选+证据，人工审核后写回 | 手工逐条 dump DOM 是真实发生过的成本，可回收 |
| 可靠性派 | 最大的钱 risk 是"自信地推荐一个能选中但语义错的选择器" | 判据必须抬高到**子树结构**，不能停在容器自身 class 名 |
| 反方 | **今天是第 1 天，只有 1 个真实站点** → §2.2 假想灵活性 | 手工适配目标本就 ≤5 分钟 3 步，工具的边际收益接近 0 |

## 二、裁定

**反方赢两条，输一条。**

- **赢（程序）**：`engine/adapters.js` 今天只有 moka 一个 `verified` 站点。按 §2.2，
  为"未来的站点"建通用摄取机器属于被明令禁止的投机建设。**据此砍掉实现派的打分／推荐／自动写回。**
- **赢（收益）**：`tests/manual-e2e.md` §generic 本来就只有 3 步、目标 ≤5 分钟。
  所谓"自动生成注册项"省下的，只是把 DOM 类名抄进文件的那点时间。
- **输（技术）**：反方称"只读探针在双约束下查不出 `bool_info` 这类错"。**这条被代码推翻** ——
  `engine.js:78` 是 `const cls = box.className`，判据停在**容器自身的类名**上；
  而 Moka 的 select 组件（`sd-Select-container` + `sd-Input-display-value`）是它的**子树**。
  判据从"自己的 class"抬到"子树结构"，只读即可查出。见 §三 的实测证据。

**结论**：建的东西要比实现派提议的薄得多——**只生成证据，不生成注册项**。
它不违反 §2.2，因为它回收的是**已经发生过一次**的成本（今天的 Moka 适配就是靠手工逐条 dump 完成的）；
它也不触发 `02` §二 原则 2 的适配器膨胀，因为它根本不产出注册项。

**`probe.mjs` 不是 R5 `probeEnv`**：R5 是运行时能力（填写时穿透 shadow DOM/iframe，防漏扫），
本节内容是开发期工具（不进持久化 bundle、不参与填写、不改变运行时行为）。二者不同，
所以 §2.4 的推迟条款不适用于本文件。

## 三、`scripts/probe.mjs`（已落地）

契约（CLI）：`node scripts/probe.mjs --session <名> [--as <选择器>] [--text] [--limit N]`

输出三类**证据**，外加页面基数：

| 字段 | 内容 | 回答什么问题 |
| --- | --- | --- |
| `containers[]` | 候选容器前缀 + `total` / `covered` / `nested` / `implied` | 哪一个才是真字段容器；有没有漏尾横线 |
| `types[]` | 类型 token 的子树特征计数（select / displayValue / readonly / file / …） | 这一类字段到底是不是下拉 → `typeMap` 的原料 |
| `texts[]` | 仅在 `--text` 下输出，标签截断 40 字 | 给人看的、便于把 token 翻译成 `blockSections` |

三条硬边界：

1. **只读**：不写入、不点击、不改任何表单状态。
2. **不推荐、不打分选出**：所有候选平铺输出，选哪个由人判断。理由：猜错的代价是静默填错，
   而这一路的全部历史教训就是"猜一个"最贵。
3. **不写回 `adapters.js`**：写回是"翻译＋受控写"两步动作，且必须带 `verified` 日期（`02` §二 原则 3）。

隐私：默认**不输出任何页面文本**。`--text` 才输出并向 stderr 打警告，整份输出视为含个人数据。

## 四、验证证据（`tests/probe.test.mjs`，3 例）

用例名带 ★ 的对应一个真实踩过的缺陷：

1. **探针能勾出零套娃的字段容器，并让尾横线差异自己浮现**
   —— 在 `tests/fixtures/moka.html` 上，输出首位是 `[class*="apply-field-"]`（total=10, nested=0），
   第二位是 `[class*="apply-f"]`（total=14, nested=4）。**即 AGENTS.md §五 校正 1 被自动复现**：
   少了尾横线就多选 4 个 wrapper。
2. **类型判据抬到子树：`bool_info` 不被判成文本框**
   —— 按 AGENTS.md §五 校正 2 的真实形态构造的 DOM 上，`bool_info` 得到 `select=3/3`、
   `readonly=0`；同时类名判据 `/select/i` 为 `false`。即两种旧判据确实都落空，只有子树判据抓得到。
   对照组 `string_info` 的 `select=0`，无误报。
3. **默认不输出任何页面文本** —— 隐私边界的回归锁。

开发过程中发现并被这两个测试挡住的两个真实缺陷：
- 排序一度用"含控件的节点数"，wrapper 被重复计数 → 零套娃的 `apply-field-` 被含 8 个套娃的 `apply-` 压过。
- 类型 key 一度取完整类名，而每个字段的后缀 hash 不同 → 每条 `n=1`，全被 `n>=2` 过滤掉，typeMap 推导静默失效。

## 五、P1 与明确的"不做"

**P1（出现第 2 个真实站点、且 generic 实测撑不住时才做）**：把 `containers`/`types` 的对应关系
翻译воре成注册项草稿的辅助环节。未做的原因是它现在没有第二个样本可校验，做了就是 §2.4 的投机条目。

**明确不做**：

1. 不自动写回 `adapters.js`（要有人的判断 + `verified` 日期）。
2. 不读页面预填值推断语义（用户今日裁决：解析器输出不可信）。
3. 不让 AI 在循环里盯着 DOM 逐条猜 —— 循环内保持确定性 JS（项目身份的原话）。
4. 不在 jsdom 测不到的地方写断言（portal 时序、body 级菜单 → 归 `manual-e2e.md`）。
5. 不预置未实测站点的适配器。`beisen` 保留 `verified: null` 就是这条的样板。
